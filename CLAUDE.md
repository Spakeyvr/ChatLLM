# Repository Instructions

## Release Notes Format

When writing release notes, use this exact structure:

This release is mainly [the kind of release it is].

Changes:

* [change]

Known issues:

* [issues]

Keep the wording concise and user-facing. Focus on what changed, not implementation details.

## Commit Summary Format

When summarizing or proposing commit messages, keep the wording concise and outcome-focused rather than implementation-heavy.
